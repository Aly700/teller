# Teller — Implementation Plan

> Each task is a whole problem for Codex (offline Maven, no Docker, no
> network); the lead runs every Testcontainers/Compose/AWS gate and commits.

**Goal:** A payments core with a policy gate — double-entry ledger,
idempotent transfers, money-aware rules, four-eyes approvals over SQS,
audit + export + reconciliation — with correctness proven under fault
injection and shown live on AWS.

**Architecture:** Seeded from AgentOps Gate (policy engine, approvals,
transactional outbox, idempotent consumer, audit, S3 export, CDK). Add the
ledger domain and a transfer API in front of the policy gate; the policy
module gains money matchers; the simulation harness gains money invariants.

**Tech Stack:** Java 21, Spring Boot 4.1.1, Spring Data JPA, Flyway,
PostgreSQL 16, AWS SDK v2 2.31 (sqs, s3), Testcontainers 2.x, jqwik 1.9.3,
Micrometer, k6, CDK 2.267; React + TypeScript (Vite) for the approvals
console.

**Spec:** the Teller section of
`../agentops-gate/docs/superpowers/specs/2026-08-29-production-grade-design.md`
(copied to `docs/superpowers/specs/2026-08-29-teller-design.md`).

### Task A: Rename, ledger schema, accounts and double-entry transfers

- Package `dev.affan.teller`; artifact `teller`; Compose/CDK names `teller-*`.
- Flyway V1 rewritten for Teller: `accounts(id, currency, status,
  ledger_balance_minor, available_balance_minor, version)`,
  `transfers(id, idempotency_key unique, from_account, to_account,
  amount_minor, currency, state, reason_code, decision_id, approval_id,
  created_at, posted_at, reversed_at)`, `entries(id, transfer_id,
  account_id, direction DEBIT|CREDIT, amount_minor, created_at)` with a
  DB constraint that every transfer's entries sum to zero; policies, rules,
  decisions, approvals, audit, outbox, processed_messages,
  idempotency_records carried over.
- Money as `long` minor units + ISO currency; never floating point.
- `POST /accounts`, `GET /accounts/{id}`, `POST /accounts/{id}/deposits`
  (funding for demos), `POST /transfers` (Idempotency-Key required),
  `GET /transfers/{id}`, `POST /transfers/{id}/reverse`.
- Transfer state machine `PENDING -> AUTHORIZED | HELD | DENIED`,
  `AUTHORIZED -> POSTED`, `HELD -> POSTED | REVERSED`, `POSTED -> REVERSED`.
  Posting writes balanced entries and updates both balances under
  optimistic locking (`@Version`); insufficient available balance → DENIED
  with reason `INSUFFICIENT_FUNDS` unless an overdraft rule allows.
- Tests: ledger arithmetic unit tests; Testcontainers integration for
  transfer → entries → balances; concurrency test (two transfers draining
  the same account concurrently never overdraw).

### Task B: Policy module with money matchers; gate on transfers

- Rule matchers add: `amountMin/amountMax` (minor units), `currency`,
  `velocity` (max N transfers per window per account), counterparty
  `allow`/`deny` lists, `fourEyesAbove` amount. Effects unchanged. First
  match wins; default deny.
- `POST /transfers` evaluates the transfer against the active policy:
  ALLOW → AUTHORIZED → POSTED in the same transaction; DENY → DENIED;
  REQUIRE_APPROVAL → HELD, available balance reserved, approval created,
  outbox message written. Approve → POSTED; deny/expire → REVERSED and the
  reservation released.
- Tests: matcher unit tests; jqwik properties for money matchers;
  integration test for each effect path; expiry releases the reservation.

### Task C: Simulation harness with money invariants

- Reuse Gate's harness; drive TransferService/PolicyService/Approval flow
  with fault injection. Invariants after every step: sum of all entries is
  zero per currency; ledger balance equals sum of posted entries; available
  balance = ledger − reservations; no account below zero without an
  overdraft rule; every HELD transfer ends POSTED or REVERSED; idempotent
  replays are no-ops; audit append-only. 200 seeds in CI, 2000 nightly,
  coverage summary printed.

### Task D: Reconciliation and export

- Nightly export of entries and audit to S3 (JSONL, date-partitioned);
  `ReconciliationJob` recomputes balances from entries and compares with
  stored balances and with the S3 export; discrepancies produce an audit
  row `RECONCILIATION_MISMATCH` and a metric. Admin trigger endpoint.

### Task E: Approvals console (React + TypeScript, Vite)

- `console/` app: list HELD transfers (amount, accounts, matched rule,
  age), approve/deny with a reason, audit view; API key entered once and
  kept in memory only. Served by the API from `/console/` (static resources
  copied at build) to avoid extra AWS cost. Vitest for the reducer/util
  code; Playwright smoke run by the lead against Compose.

### Task F: Observability, performance, CDK, live capture, README (lead-heavy)

- Metrics, alarms, dashboard, runbook as in Gate. CDK stacks renamed to
  `Teller*`; deploy for capture; k6 `load/transfers.js`; chaos (kill task
  mid-batch with HELD transfers; poison message; replay); evidence in
  `docs/evidence/`; ADRs; case-study README; destroy.
